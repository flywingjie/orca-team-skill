# Worker 回报模板

> 结算时必须使用；失败时使用失败版。

## 成功

```text
做了什么：
- <改动 1>
- <改动 2>
补丁包：patches/<单号>/<worker>/

凭什么算做完：
- `<命令 1>` → <结果>
- `<命令 2>` → <结果>
证据：evidence/<文件>

还有什么没做：
- <未覆盖项 / 已知限制 / 需要谁决定什么>
```

## 失败

```text
结果：失败

卡点：
- <具体错误 / 缺少的依赖 / 越界冲突>

已尝试：
- `<命令>` → <结果>
- `<命令>` → <结果>

需要：
- <谁做什么决定 / 提供什么>

已有产出：
- <补丁 / 部分改动 / 证据路径>
```

## 阻塞（未开工或中途停下）

```text
结果：阻塞

阻塞点：<一句话>
需要：<谁决定什么>
已确认的事实：<读过的文件 / 跑过的命令>
建议：<可选方案，不超过 2 个>
```

## 纪律

- 不得把失败写成“基本完成”。
- 不得省略失败命令的输出。
- 不得声称跑过没跑的命令。
- 不得把“终端空闲”当作完成。
