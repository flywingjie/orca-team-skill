# 适配：纯人工

## 1. 适用

- 没有可用的多 agent 编排工具；
- 或某个 agent 无法被编排，只能人工在 IDE 里执行；
- 或作为兜底流程。

## 2. 隔离

```bash
git fetch origin
git worktree add ../wt-<单号> -b feature/<单号>-<短名> origin/main
cd ../wt-<单号>
```

规则：

- 一任务一工作区；不共享工作目录并行。
- 基线用 `origin/main`，不用本地 `main`。
- 任务结束显式处置工作区（保留 / 删除）。

## 3. 派单

1. 复制 `templates/task-ticket.md`，填五段。
2. 把“角色卡 + 工单 + 纪律尾巴”作为任务说明交给执行人/agent。
3. 在工单文件里记录：单号、分支、工作区、开始时间、状态。

## 4. 状态与回报

- 状态写在工单文件的「状态」段，或工作区根的 `STATUS.md`。
- 完成时写回报三句；失败时写失败版。
- 协调者（可以是人）定期读状态文件，不依赖即时消息。

## 5. 闸口

- 规格门：拍板人书面确认（邮件/工单评论/文档签字）。
- 设计门：协调者核对门禁输出后请拍板人确认。
- 交付门：拍板人签字。

没有自动闸口时，**必须**在进入下一步前拿到明确文字确认；不得“先做后补”。

## 6. 验收

按 `references/07-verification.md`：

1. 范围关：人工核对 diff 路径 ⊆ 归属清单。
2. 正确关：逐条执行验收命令，记录输出。
3. 集成关：合入集成分支后跑回归。
4. 逐文件 `git add`，Conventional Commits。
5. 更新进度与风险。

## 7. 降级清单

| 缺什么 | 降级做法 | 代价 |
|---|---|---|
| 无编排工具 | 工单文件 + 状态文件 | 协调者要主动读 |
| 无自动回报 | 工单「回报」段 | 结算延迟 |
| 无自动闸口 | 文字确认后继续 | 靠纪律 |
| 无独立工作区 | 一分支一任务，串行 | 并行度 1 |
| 无自动门禁 | 人工执行命令并贴输出 | 易漏跑，需清单 |

## 8. 人工检查清单

- [ ] 工单五段齐全
- [ ] 工作区基线正确
- [ ] 归属文件互不相交
- [ ] 派单说明含角色卡与纪律
- [ ] 状态文件已建
- [ ] 验收命令逐条执行
- [ ] 补丁/diff 路径不越界
- [ ] 逐文件提交
- [ ] 进度与风险回写
- [ ] 工作区处置完成
