# 04 并行边界与文件所有权

> 对应 `SPEC.md` §7。并行期最常见的事故不是“写错代码”，而是两个 agent 都认为自己该改同一个文件。

## 1. 五条硬规则

### P-1 契约分两层

| 层 | 内容 | owner | 其他任务 |
|---|---|---|---|
| **契约定义** | 模型、schema、错误码、权限映射 | `contract` 单 | 只读；需改则回流 |
| **契约产物** | 生成的 OpenAPI / 类型文件 / 错误码清单 | `integration` 单（末波统一生成） | 只读；不得手写 |

**为什么**：前后端并行期如果都能改契约，合并时必然冲突；把“定义”前置、“产物”末波统一，
并行期双方对着同一份已冻结定义实现。

### P-2 共享底座串行

以下内容牵一发动全身，必须由单一任务独占，其他任务只消费接口：

- 主数据与编码规则；
- 权限、组织、审计；
- 批次/序列号追溯链；
- 单据状态机内核、幂等、过账/冲销；
- 跨域调用的公共契约。

**判定**：如果一个改动会影响两个以上域的行为，它就是共享底座，不并行。

### P-3 迁移号段分配死

- 拆单时就分配号段，写进工单。
- 两张单不得出现同一个迁移号。
- 已发布迁移只增不改；修正只能新增迁移。
- 号段冲突视为拆单错误，必须回退重拆，不得“边跑边协调”。

### P-4 同一文件不并行

以下文件默认视为“共享文件”，只能由单一 owner 在收口阶段改：

- 依赖清单与 lockfile；
- 路由注册表；
- 菜单/导航注册；
- 类型出口与契约产物；
- 全局配置与启动入口。

两个任务都需要改同一文件时，三选一：

1. 合并为一张单；
2. 拆出“共享文件专项单”，串行执行；
3. 由集成单在收口阶段统一改。

### P-5 并行度、链深、模型互斥

- 并行度 ≤ 8；
- 依赖链深 ≤ 4；
- 同一时刻在跑的任务不得使用同一底层模型家族；
- 派单前做模型可达预检；可达不足时降并行，不得用同一模型硬凑。

## 2. 文件所有权表

拆单时必须产出如下表，附在波次计划里：

| 任务 | 独占文件 | 只读依赖 | 交接点 |
|---|---|---|---|
| API-014 | `server/api/orders.py`、`server/tests/test_orders.py` | `server/models/order.py` | 契约冻结后开工 |
| WEB-021 | `web/src/pages/Orders.tsx`、`web/src/services/orders.ts` | 生成的类型文件 | API-014 契约冻结后开工 |
| INT-001 | 契约产物、路由注册 | 上述全部 | 两支补丁齐后执行 |

**规则**：

- 同一行内的文件集合与其他行不得有交集。
- 有交集时，必须先解决所有权，再派单。
- 只读依赖不是“可以改”，只是“可以读”。

## 3. 同工作区多 worker 的纪律

同任务的前后端可以共用一个 worktree，但必须：

1. 「归属」段列出互不相交的文件集合；
2. 所有 worker 禁止 `checkout` / `restore` / `clean` / `reset` / `stash`
   （这些命令会毁掉他人未提交改动）；
3. 新增文件先登记 intent-to-add，否则 diff 不含它；
4. 每个 worker 各自生成补丁，不互相覆盖；
5. 任一 worker 发现需要改他人文件，停下上报，不“顺手改一下”。

## 4. 波次计算

```text
输入：任务列表（id, depends_on, files, model）
输出：波次列表

1. ready = 依赖全部结算的任务
2. 按 files 做冲突检测：有交集的任务分到不同波
3. 按 model family 去重：同波不重复
4. 每波最多 8 个
5. 重复直到所有任务排完
6. 校验链深 ≤ 4
```

工具：`scripts/plan.py`。

## 5. 冲突处置

| 冲突类型 | 处置 |
|---|---|
| 文件所有权重叠 | 停派，重拆单或合并 |
| 同一文件出现在两个补丁里 | 集成关判 `file-multi-owner` 失败；回到拆单阶段合并为一张单或拆「共享文件专项单」（`P-4`） |
| 契约定义冲突 | 回流 `contract` 单，统一改 |
| 契约产物冲突 | 由 `integration` 单统一生成，实施单不改 |
| 迁移号冲突 | 回退重拆，重新分配号段 |
| 语义冲突（两边都合理但行为不同） | 停下上报，由设计/拍板人裁决 |

**禁止**：在集成阶段“现场发挥”改契约或改业务语义来消解冲突；那只会在下一轮制造更大的偏差。

## 6. 并行前的检查清单

- [ ] 每个任务的依赖已结算
- [ ] 文件所有权表无交集
- [ ] 迁移号段已分配且不重复
- [ ] 契约定义已冻结；契约产物 owner 已确定
- [ ] 同波任务模型家族不重复
- [ ] 并行度 ≤ 8，链深 ≤ 4
- [ ] 每个 worker 的基线正确
- [ ] 每个任务都有补丁包路径与回报通道
